# GroopE_Project

卒業制作Eチーム

## アプリの起動

プロジェクトの仮想環境とOllamaを準備した後、リポジトリ直下の`run.bat`をダブルクリックするとFlaskアプリを起動できます。バッチファイルはOllamaの稼働とモデルを確認し、停止中の場合はOllamaを最小化した別ウィンドウで起動してから、プロジェクト内の`venv`を使用して`apps:create_app`を起動します。Ollamaはアプリ終了後も稼働します。起動時にOllamaやモデルが見つからない場合は、表示された案内に従ってください。

コマンドから起動する場合は、仮想環境を有効にして次を実行します。

```powershell
flask --app apps:create_app run --debug
```

## データベース

SQLiteのデータベースは`instance/groope.db`です。一般・店舗アカウントは`account`テーブルに保存され、パスワードはハッシュ化されます。ログアウト時は確認ダイアログで「OK」を選ぶとログアウトし、「キャンセル」を選ぶとログイン状態を維持します。JavaScriptが無効な場合は確認画面を使用します。

初回起動時、またはマイグレーションを取得した後は、アプリを起動する前に仮想環境を有効にしてスキーマを更新してください。

```powershell
flask --app apps:create_app db upgrade
```

マイグレーションは既存データを残したまま必要なテーブルや列を追加します。

## 外食・レシピ検索

「外で食べる」の検索欄にある「気分から選ぶ」を開くと、選んだ気分が検索欄に入力されます。

「外で食べる」では、入力文と料理ジャンルをローカルのOllamaに送り、入力文とAIが提案した検索語をGoogle Places APIで検索します。AIには、ファミレスや居酒屋など店舗の種類が指定された場合はそれを優先し、指定がない場合は気分に合う料理や飲食店を提案するよう指示しています。AIの出力や検索結果が希望に必ず一致するとは限りません。AIが利用できない場合はエラーを表示し、入力文のみで検索します。予算や現在地はAIには送りません。ブラウザで現在地を許可する必要があり、現在地はGoogle Places APIの検索に使われます。検索結果画面では、現在地からの直線距離を1・3・5・10kmから選んで絞り込めます（初期値は10km）。最大10km以内の取得済み店舗を再検索せずに絞り込み、距離が不明な店舗は除外します。絞り込みで非表示の店舗はルーレットの対象になりません。

検索距離に「制限なし」を選ぶと再検索し、国や距離を制限せずに表示します。国の取得にGeocoding APIは使いません。距離が不明な店舗は除外します。Googleの店舗検索結果は検索語ごとに最大10件であり、すべての店舗を網羅するものではありません。距離制限ありと制限なしの切り替え時にはAIの提案と店舗検索が再実行されます。

AIには「がっつり」を食べ応えのある料理として解釈し、辛い料理の希望がないときに辛さを推測しないよう指示しています。辛い料理を希望する場合は入力に明記してください。入力文自体もPlaces APIで検索するため、AIの提案に含まれない店舗が表示される場合があります。

1. [Ollama](https://ollama.com/)をインストールします。手動でFlaskを起動する場合はOllamaも起動してください。
2. PowerShellで `ollama pull llama3.1` を実行してモデルを取得します。
3. Google Cloudで課金を設定し、Places API (New) を有効にしてAPIキーを作成します。キーはPlaces APIに制限し、サーバーからのリクエストに適した制限を設定してください。料金はGoogleの料金表をご確認ください。
4. APIキーをWindowsのユーザー環境変数に登録します。PowerShellで `setx GOOGLE_MAPS_API_KEY "取得したAPIキー"` を実行し、VS Codeとターミナルを開き直してください。`setx`は新しく起動したプロセスから有効になります。APIキーをソースコードやGitに登録しないでください。
   現在のPowerShellだけで一時的に使う場合は、`$env:GOOGLE_MAPS_API_KEY = "取得したAPIキー"` を設定して、その同じPowerShellからアプリを起動してください。この設定はターミナルを閉じると失われます。
5. 同じPowerShellで `.\run.bat` を実行し、「外で食べる」に入力して検索し、位置情報を許可します。ブラウザの位置情報にはlocalhostまたはHTTPSが必要です。

OllamaのAPIは `127.0.0.1:11434` を使用します。別のインストール済みモデルを使う場合は、アプリの起動前にPowerShellで `$env:OLLAMA_MODEL = "モデル名"` を設定してください。初回の応答には時間がかかる場合があります。

予算を入力すると、Googleの価格帯で大まかに絞り込みます。アプリ独自の目安として、1,000円未満は「安め」、1,000円以上は「普通」まで、3,000円以上は「高め」まで、10,000円以上は「非常に高い」までを対象とします。価格帯は料理の実際の値段ではなく、予算内で食べられる保証はありません。価格帯が未登録の店舗は結果から除外される場合があります。予算未入力時は価格帯で絞り込みません。外食検索では重複を除いた検索語で最大4回のPlaces API利用が発生します。最初の店舗検索後、残りを並行して実行します。並行検索中にエラーが発生した場合、他のリクエストも送信済みの可能性があります。AIと各Places検索の所要時間、および検索全体の所要時間は、Flaskの実行コンソールに`search_timing`ログとして秒単位で出力されます。検索語や位置情報はログに含めません。

「家で食べる」では、SQLiteに保存されたレシピの名前・材料・作り方を入力文で部分一致検索し、材料と作り方を表示します。位置情報、AI、Places APIは使用しません。ログイン中のレシピ投稿は写真を含めデータベースに保存され、投稿者のマイページ、検索結果、ホームの新着レシピと詳細画面で表示されます。写真はPNG・JPEG・GIF・WebP形式、1枚300KB以下です。材料と工程は各50件以内です。以前ブラウザー内に保存した投稿は、投稿画面またはマイページを開くと削除され、データベースには移行されません。レシピ詳細と店舗詳細では、ログイン中の一般ユーザーが1〜5の星評価と最大1000文字のコメントを投稿・更新できます。レビューはデータベースに保存され、一覧・平均評価・並び替えに反映されます。ログイン中の一般ユーザーは、レシピ詳細・店舗詳細からお気に入りを登録・解除でき、マイページのお気に入り画面で一覧を確認できます。お気に入りはアカウントごとにデータベースへ保存されます。

店舗アカウントでは、一般ユーザー向けのお気に入り、カロリー計算、レシピ投稿・検索、新着レシピのリンク、予約申請、レビュー投稿を無効にします。店舗検索と店舗連携、店舗管理のメニュー登録・予約管理は利用できます。

外食検索では、店舗アカウントが登録したメニュー名も、入力文と双方向の部分一致で検索します。例えば「パン」と「アンパン」はどちらの方向でも一致します。全角・半角と英字の大文字・小文字は正規化しますが、意味による類似検索やひらがな・カタカナの変換は行いません。Google未連携の店舗は、店舗名でも部分一致検索できます。登録メニューから見つかった店舗はGoogle検索結果と重複せずに表示され、一致したメニュー名と価格を確認できます。予算指定時は予算以下のメニューだけを対象にします。ジャンルでメニューを絞り込むことはできません。Google検索に含まれない連携済み店舗はPlace Details (New) から位置と店舗情報を取得するため、追加料金が発生する場合があります。位置が不明な店舗は表示されません。店舗アカウントのPlace ID連携はデモです。

Google未連携の店舗を表示するには、店舗アカウントでログインし、店舗管理の「店舗の位置」で緯度・経度を登録してください。名前、住所、位置は登録者の申告であり、架空店舗にも利用できます。位置未登録では検索結果に表示されません。Googleと連携した店舗はGoogleの情報で表示します。未連携店舗への予約はデモであり、実際の予約として利用できません。デモ予約には店舗管理画面とマイページにその旨を表示します。

検索結果にはGoogle MapsのデータとGoogle未連携の店舗アカウントが含まれます。検索せずに直接表示した店舗一覧はサンプルであり、検索条件による絞り込みは行いません。

気分検索の「店舗詳細」は選択した店舗の情報と写真をPlaces APIから取得します。写真が登録されていない場合はNoImage画像を表示し、写真取得時のエラーは画面に表示します。詳細表示ごとにPlace Details (New) および写真取得の利用料金が発生する場合があります。お気に入り店舗の一覧表示でも店舗名と住所の取得にPlace Details (New) を利用します。お気に入りにはPlace IDのみを保存し、Googleの店舗情報はデータベースに保存しません。紹介文、アクセス情報は未対応です。ログイン中の一般ユーザーは店舗レビューを投稿・更新できます。検索結果への戻りはブラウザの履歴を使用し、履歴の状態によってはフォームの再送信確認が表示されます。

一般ユーザーの設定画面では、名前、メールアドレス、アレルギーをアカウントごとに保存できます。ログイン設定でメールアドレスの自動入力を有効にすると、そのブラウザーにメールアドレスだけを保存します。パスワードはアプリには保存せず、ブラウザーのパスワードマネージャーの挙動も制御しません。共有端末では無効にしてください。店舗詳細では、登録メニュー名から推定したアレルゲン候補と設定済みアレルギーを照合し、一致候補があれば警告します。現在の判定モデルは「そば」を判定できず、メニュー名だけでは原材料や調理時の混入も分かりません。候補が表示されない場合も安全の保証にはならないため、必ず店舗に確認してください。現在地利用・健康管理モード・好き嫌い・宗教の設定は未実装のため変更できません。以前保存した値は保持されますが、機能には反映されません。現在地の取得はブラウザーの位置情報の許可設定で管理してください。

写真でのカロリー計算は、料理名・材料・量・推定カロリーを自動保存し、マイページの履歴で確認できます。材料の編集も自動保存されます。写真そのものは履歴に保存しません。保存中は画面を離れず、保存失敗時は画面の再試行ボタンを押してください。未照合の材料を含む場合、表示されるカロリーは照合済み材料の小計です。

ログイン中の一般ユーザーが店舗詳細を表示すると、店舗のPlace IDと閲覧日時をアカウントごとに保存し、マイページの閲覧履歴に新しい順で表示します。同じ店舗を再度表示すると新しい履歴が追加されます。店舗情報の取得に失敗した場合は記録しません。履歴一覧でも店舗名と住所をPlace Details (New) から取得するため、利用料金が発生する場合があります。ログイン前の閲覧は記録されず、今回の変更以前の閲覧も表示されません。レシピ履歴は未対応です。

店舗アカウントでログインすると、検索結果からPlace ID連携を申請できます。現在の確認コードはデモ用で、実際のSMSは送信されず、コードが画面に表示されます。Place IDが連携済みの店舗には検索結果にデモ連携済みバッジを表示します。実際に運用する場合はSMS事業者の接続と本人確認手順が必要です。

## 予約

一般ユーザーは、店舗アカウントがあり、Google連携または店舗位置の登録がある店舗に予約を申請できます。未連携店舗への申請はデモモードでのみ利用できます。今回のデータベース移行以前の予約も、安全のためデモ予約として表示します。店舗側は予約管理で申請を承認またはキャンセルでき、利用者はマイページで状態を確認できます。承認されるまで予約は確定しません。確定後も店舗はキャンセルできます。通知機能、利用者によるキャンセル、営業時間や空席の自動確認はありません。日時はサーバーのローカル時刻で扱うため、日本向けの利用時はサーバーを日本時間に設定してください。以前のブラウザー内の試作予約は移行されません。

**店舗連携はデモであり、実際の店舗の本人確認はできていません。実店舗への予約として利用しないでください。** 本番運用には店舗の本人確認、セキュリティ対策、通知や運用手順の整備が必要です。

## 写真でカロリー計算

一般ユーザーでログイン後、「写真でカロリー計算」で料理の写真を選び、推定ボタンを押すとGemini 3.5 Flash-Liteが料理名、材料と分量の候補を返します。写真は選択後に表示され、「画像を変更する」から選び直せます。食品成分表から食品を自動選択し、食品100g当たりのエネルギーから合計を計算します。自動選択された食品の種類や調理状態が実際と異なる場合があります。「材料一覧を見る」を開いて確認し、必要に応じて「材料を編集」から食品・分量を変更してください。材料の追加・削除も可能です。自動照合できない材料がある場合は未計算件数と照合済み材料の小計を表示し、すべて未照合なら合計は表示しません。成分値の出典は[日本食品標準成分表（八訂）増補2023年](https://www.mext.go.jp/a_menu/syokuhinseibun/mext_00001.html)です。

利用前に[Google AI Studio](https://aistudio.google.com/)でGemini APIキーを取得し、アプリ起動前のPowerShellで `$env:GEMINI_API_KEY = "取得したAPIキー"` を設定して、同じPowerShellから `.\run.bat` を実行してください。キーはソースコードやGitに登録しないでください。Gemini APIは無料枠の制限や有料枠の料金があり、利用可能な枠はアカウントやモデルにより異なります。[料金表](https://ai.google.dev/gemini-api/docs/pricing)と利用状況を確認してください。

推定ボタンを押すと写真がGoogleに送信されます。無料枠では送信内容がGoogleのサービス改善に使用される場合があります（[Gemini API利用規約](https://ai.google.dev/gemini-api/terms)）。画像はブラウザでJPEGに変換して送信し、記録としては保存しませんが、サーバー上に一時ファイルが作られる場合があります。写真から材料、油、調味料や量を正確に判断することはできないため、必ず候補を確認してください。結果は目安であり、医療・栄養管理上の判断には使用しないでください。

## アレルゲン候補の表示

レシピ詳細では登録された料理名・材料・説明文を、店舗詳細では店舗アカウントが登録したメニュー名を、Hugging Faceの[`adisyonist/14-allergens-0.3b`](https://huggingface.co/adisyonist/14-allergens-0.3b)で分析して候補を表示します。店舗メニュー未登録時は判定できないことを表示します。モデルのダウンロード先はリポジトリ直下の`14-allergens-0.3b`で、約1.1GBのモデルファイルはGitに含めません。初回の詳細表示時にモデルを読み込みます。初回準備時にプロジェクト仮想環境から以下を実行してください。

```powershell
.\venv\Scripts\python.exe -m pip install torch transformers
.\venv\Scripts\hf.exe download adisyonist/14-allergens-0.3b --local-dir .\14-allergens-0.3b
```

表示は誤りや見落としがあり得る参考情報で、原材料や調理時の混入を網羅しません。候補が表示されない場合も安全の保証にはならないため、アレルギーがある場合は必ず店舗や投稿者に確認してください。

# GitHubへのプッシュ手順

このリポジトリで開発するときは、以下の手順に従ってください。

## 1. リポジトリをクローンする（初回のみ）

```powershell
git clone https://github.com/mitentist0812-code/GroopE_Project.git
cd GroopE_Project
```

## 2. 最新のmainブランチを取得する

作業を始める前に、`main`ブランチの最新状態を取得します。

```powershell
git switch main
git pull origin main
```

## 3. 作業用ブランチを作成する

`main`ブランチに直接変更を加えず、作業内容に応じたブランチを作成します。

```powershell
git switch -c feature/login
```

ブランチ名の例：

- `feature/`: 新機能の追加（例：`feature/search`）
- `fix/`: バグの修正（例：`fix/login-error`）
- `design/`: デザインの変更（例：`design/header`）

## 4. ファイルを編集する

VS Codeなどで担当箇所を編集し、変更内容を確認します。

```powershell
git status
```

## 5. 変更をコミットする

```powershell
git add .
git commit -m "ログイン画面を作成"
```

コミットメッセージは、実際の変更内容に合わせてください。

## 6. GitHubにプッシュする

作成した作業用ブランチをGitHubにアップロードします。

```powershell
git push -u origin feature/login
```

同じブランチに追加の変更をプッシュする場合は、変更をコミットした後に次のコマンドを実行します。

```powershell
git push
```

## 7. Pull Requestを作成する

プッシュ後、GitHubでリポジトリを開き、作業用ブランチからPull Requestを作成します。

1. 「Compare & pull request」を選択します。
2. `base`が`main`になっていることを確認します。
3. 変更内容を記入します。
4. 「Create pull request」を選択します。

Pull Requestは、管理者または他のメンバーによる確認後に`main`へマージします。

## 8. 次回以降の作業

リポジトリ直下の`start-work-branch.bat`を実行すると、最新の`main`を取得して作業用ブランチを作成できます。`feature`（新機能）、`fix`（バグ修正）、`design`（デザイン変更）を選び、ブランチ名を入力してください。たとえば`feature`と`search`を選ぶと`feature/search`が作成されます。

コマンドで行う場合は、次のように実行します。ブランチ名は作業内容に合わせて変更してください。

```powershell
git switch main
git pull origin main
git switch -c feature/search
```

## 開発時の注意事項

- `main`ブランチへ直接プッシュしないでください。
- 必ず作業用ブランチを作成してください。
- 作業開始前に`main`ブランチを最新の状態にしてください。
- コミットメッセージには変更内容を簡潔に記述してください。
- `main`への反映はPull Requestを通してください。
- `.env`など、パスワードや秘密情報を含むファイルはプッシュしないでください。
