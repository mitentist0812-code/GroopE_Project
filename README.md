# GroopE_Project

卒業制作Eチーム

## アプリの起動

プロジェクトの仮想環境とOllamaを準備した後、リポジトリ直下の`run.bat`をダブルクリックするとFlaskアプリを起動できます。バッチファイルはOllamaの稼働とモデルを確認し、停止中の場合はOllamaを最小化した別ウィンドウで起動してから、プロジェクト内の`venv`を使用して`apps:create_app`を起動します。Ollamaはアプリ終了後も稼働します。起動時にOllamaやモデルが見つからない場合は、表示された案内に従ってください。

コマンドから起動する場合は、仮想環境を有効にして次を実行します。

```powershell
flask --app apps:create_app run --debug
```

## データベース

SQLiteのデータベースは`instance/groope.db`です。一般・店舗アカウントは`account`テーブルに保存され、パスワードはハッシュ化されます。

初回起動時、またはマイグレーションを取得した後は、アプリを起動する前に仮想環境を有効にしてスキーマを更新してください。

```powershell
flask --app apps:create_app db upgrade
```

マイグレーションは既存データを残したまま必要なテーブルや列を追加します。

## 外食・レシピ検索

「外で食べる」では、入力文と料理ジャンルをローカルのOllamaに送り、入力文とAIが提案した検索語をGoogle Places APIで検索します。AIには、ファミレスや居酒屋など店舗の種類が指定された場合はそれを優先し、指定がない場合は気分に合う料理や飲食店を提案するよう指示しています。AIの出力や検索結果が希望に必ず一致するとは限りません。AIが利用できない場合はエラーを表示し、入力文のみで検索します。予算や現在地はAIには送りません。ブラウザで現在地を許可する必要があり、現在地はGoogle Places APIの検索に使われます。検索結果画面では、現在地からの直線距離を1・3・5・10kmから選んで絞り込めます（初期値は10km）。最大10km以内の取得済み店舗を再検索せずに絞り込み、距離が不明な店舗は除外します。Google Places APIが返す検索結果を絞り込むため、範囲内のすべての店舗が表示されるとは限りません。絞り込みで非表示の店舗はルーレットの対象になりません。

AIには「がっつり」を食べ応えのある料理として解釈し、辛い料理の希望がないときに辛さを推測しないよう指示しています。辛い料理を希望する場合は入力に明記してください。入力文自体もPlaces APIで検索するため、AIの提案に含まれない店舗が表示される場合があります。

1. [Ollama](https://ollama.com/)をインストールします。手動でFlaskを起動する場合はOllamaも起動してください。
2. PowerShellで `ollama pull llama3.1` を実行してモデルを取得します。
3. Google Cloudで課金を設定し、Places API (New) を有効にしてAPIキーを作成します。キーはPlaces APIに制限し、サーバーからのリクエストに適した制限を設定してください。料金はGoogleの料金表をご確認ください。
4. APIキーをWindowsのユーザー環境変数に登録します。PowerShellで `setx GOOGLE_MAPS_API_KEY "取得したAPIキー"` を実行し、VS Codeとターミナルを開き直してください。`setx`は新しく起動したプロセスから有効になります。APIキーをソースコードやGitに登録しないでください。
   現在のPowerShellだけで一時的に使う場合は、`$env:GOOGLE_MAPS_API_KEY = "取得したAPIキー"` を設定して、その同じPowerShellからアプリを起動してください。この設定はターミナルを閉じると失われます。
5. 同じPowerShellで `.\run.bat` を実行し、「外で食べる」に入力して検索し、位置情報を許可します。ブラウザの位置情報にはlocalhostまたはHTTPSが必要です。

OllamaのAPIは `127.0.0.1:11434` を使用します。別のインストール済みモデルを使う場合は、アプリの起動前にPowerShellで `$env:OLLAMA_MODEL = "モデル名"` を設定してください。初回の応答には時間がかかる場合があります。

予算を入力すると、Googleの価格帯で大まかに絞り込みます。アプリ独自の目安として、1,000円未満は「安め」、1,000円以上は「普通」まで、3,000円以上は「高め」まで、10,000円以上は「非常に高い」までを対象とします。価格帯は料理の実際の値段ではなく、予算内で食べられる保証はありません。価格帯が未登録の店舗は結果から除外される場合があります。予算未入力時は価格帯で絞り込みません。外食検索では重複を除いた検索語で最大4回のPlaces API利用が発生します。最初の店舗検索後、残りを並行して実行します。並行検索中にエラーが発生した場合、他のリクエストも送信済みの可能性があります。

「家で食べる」では、SQLiteに保存されたレシピの名前・材料・作り方を入力文で部分一致検索し、材料と作り方を表示します。位置情報、AI、Places APIは使用しません。レシピの投稿・詳細画面は現時点ではサンプルで、データベースへの投稿機能は未実装です。

検索した店舗一覧はGoogle Mapsのデータです。検索せずに直接表示した店舗一覧はサンプルであり、検索条件による絞り込みは行いません。

気分検索の「店舗詳細」は選択した店舗の情報と写真をPlaces APIから取得します。写真が登録されていない場合はNoImage画像を表示し、写真取得時のエラーは画面に表示します。詳細表示ごとにPlace Details (New) および写真取得の利用料金が発生する場合があります。紹介文、アクセス情報および実店舗の予約・お気に入り・レビュー機能は未対応です。検索結果への戻りはブラウザの履歴を使用し、履歴の状態によってはフォームの再送信確認が表示されます。

店舗アカウントでログインすると、検索結果からPlace ID連携を申請できます。現在の確認コードはデモ用で、実際のSMSは送信されず、コードが画面に表示されます。Place IDが連携済みの店舗には検索結果にデモ連携済みバッジを表示します。実際に運用する場合はSMS事業者の接続と本人確認手順が必要です。

## アプリ構成

- `apps/auth`: ログインと会員登録
- `apps/home`: ホームと検索結果
- `apps/recipes`: レシピ
- `apps/users`: マイページ、設定、お気に入り、履歴
- `apps/restaurants`: 店舗、メニュー、予約
- `apps/nutrition`: カロリー計算
- `apps/templates/shared`: 共通レイアウト
- `apps/static`: CSS（`css`）、画像（`img`）、JavaScript（`js`）

# GitHubへのプッシュ手順

このリポジトリで開発するときは、以下の手順に従ってください。

## 1. リポジトリをクローンする（初回のみ）

```powershell
git clone https://github.com/mitentist0812-code/GroopE_Project.git
cd GroopE_Project
```

## 2. 最新のmainブランチを取得する

作業を始める前に、`main`ブランチの最新状態を取得します。

```powershell
git switch main
git pull origin main
```

## 3. 作業用ブランチを作成する

`main`ブランチに直接変更を加えず、作業内容に応じたブランチを作成します。

```powershell
git switch -c feature/login
```

ブランチ名の例：

- `feature/`: 新機能の追加（例：`feature/search`）
- `fix/`: バグの修正（例：`fix/login-error`）
- `design/`: デザインの変更（例：`design/header`）

## 4. ファイルを編集する

VS Codeなどで担当箇所を編集し、変更内容を確認します。

```powershell
git status
```

## 5. 変更をコミットする

```powershell
git add .
git commit -m "ログイン画面を作成"
```

コミットメッセージは、実際の変更内容に合わせてください。

## 6. GitHubにプッシュする

作成した作業用ブランチをGitHubにアップロードします。

```powershell
git push -u origin feature/login
```

同じブランチに追加の変更をプッシュする場合は、変更をコミットした後に次のコマンドを実行します。

```powershell
git push
```

## 7. Pull Requestを作成する

プッシュ後、GitHubでリポジトリを開き、作業用ブランチからPull Requestを作成します。

1. 「Compare & pull request」を選択します。
2. `base`が`main`になっていることを確認します。
3. 変更内容を記入します。
4. 「Create pull request」を選択します。

Pull Requestは、管理者または他のメンバーによる確認後に`main`へマージします。

## 8. 次回以降の作業

リポジトリ直下の`start-work-branch.bat`を実行すると、最新の`main`を取得して作業用ブランチを作成できます。`feature`（新機能）、`fix`（バグ修正）、`design`（デザイン変更）を選び、ブランチ名を入力してください。たとえば`feature`と`search`を選ぶと`feature/search`が作成されます。

コマンドで行う場合は、次のように実行します。ブランチ名は作業内容に合わせて変更してください。

```powershell
git switch main
git pull origin main
git switch -c feature/search
```

## 開発時の注意事項

- `main`ブランチへ直接プッシュしないでください。
- 必ず作業用ブランチを作成してください。
- 作業開始前に`main`ブランチを最新の状態にしてください。
- コミットメッセージには変更内容を簡潔に記述してください。
- `main`への反映はPull Requestを通してください。
- `.env`など、パスワードや秘密情報を含むファイルはプッシュしないでください。
